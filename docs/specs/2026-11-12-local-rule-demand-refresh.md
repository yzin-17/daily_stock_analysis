# 本地收费规则按需刷新与覆盖推进

## 范围与行为

本地资料的公共收费查询超出已有日期覆盖时，先按已选来源尝试取得最新资料。复用已登记的官方文档、有限抓取、正文解析和监测记录；不更改路由、监测配置、历史原件或冻结结果。此规格服务于主仓自主竞技场 T06.2，同时保持历史费用消费者兼容。

- AC01：仅日期覆盖不足触发刷新；证券范围不符、资料冲突、损坏或原范围内读取不触发远程读取。运行请求通过既有来源控制，直接纯读取没有运行存储上下文时保留只读行为。
- AC02：成功检查完整资料集合后，新增／变更列表为空时推进已核验的覆盖终点，并复用末段费用回答新范围。新范围不得超过实际检查日；不以最新文档猜测基线以前的历史制度。
- AC03：新增／变更以绑定资料包指纹的基线比较。首次取得且缺少基线的资料属于新增资料；不能把下一次“相对上次抓取无变化”当作旧费用已获认证。新资料和失败都保留正文或稳定原因，不伪装为空。
- AC04：沿用正文解析的非空、大小、重定向、验证码和超时门禁。任一必要文档失败、未知、无正文或未完整检查时，不推进覆盖。
- AC05：原始资料不变，覆盖投影、检查证据和失败冷却独立持久化；同一资料包复用已核验范围，资料包或来源控制变化使旧投影失效。并发请求只允许一个同步检查，其余明确返回处理中。
- AC06：通过真实有限 HTTP 抓取器、隔离 SQLite 和 Data 请求链验证正常无变化、新资料、失败、重开、并发及晚到结果。受控验证和真实官方资料／目标部署分别记录。
