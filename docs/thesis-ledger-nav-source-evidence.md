## 精确净值原文入口

2026-09-30，对应主仓 E01-N2.3.2.1。`data_provider.eastmoney_fund_nav.read_fund_nav_evidence(fund_code)` 读取同一东方财富移动端端点，返回不可变 `NavRawEvidence`，使用 `reader_revision=eastmoney-fund-nav-raw-v1`；既有 `read_fund_nav` 从该证据构造原有四列 DataFrame，Provider 对外排序和显示接口不变。

- 输入为六位 ASCII 基金代码。请求使用显式 TLS 校验、连接/读取超时、55 秒整批预算，不内部重试；每页 1000 行，最多 100 页/100000 行，每页最多 4 MiB，整批最多 32 MiB。
- `pages` 按请求页序保存完整 UTF-8 `raw_response` 和 SHA-256；`records` 保持来源页内顺序，保存 `valuation_date`、未经浮点转换的 `unit_nav`、页索引、该行完整 JSON 原文及摘要。解析按顶层 `Datas` 定位，保留字段顺序、空白、额外原生字段及数字词法，不将记录重新编码后冒充原文。
- 净值只接受规范正十进制字符串，拒绝浮点数、布尔值、零、负数、指数、空白或非数值表达。日期有效且全批唯一，不允许晚于真实采集日的上海日期；重复 JSON 字段或非标准 JSON 数值拒绝。
- `captured_at` 是最后一页校验完成后的真实 UTC 时刻，不代表逐条净值历史发布时间。`content_hash` 绑定请求基金、端点、Reader 修订及按页排序的原响应摘要；总量和页长度不一致或任何预算/传输/记录失败时不发布部分证据。
- `total_count=0` 可返回完整空来源证据，以保留既有显示 Reader 空表语义；后续回测生产者仍须对非空预期估值窗口失败关闭。

此入口不读取或修改 Policy/Admission，不授予任何公开净值路由或严格 PIT 资格。分页总量完整只证明当前来源自报行数已取得；预期估值日、历史版本、基金申赎暂停与研究可见性规则仍由 E01-N2.3.2.2/3 接入和验收。`reader_revision` 是本 Reader 实现修订，不能冒充源端历史版本。
