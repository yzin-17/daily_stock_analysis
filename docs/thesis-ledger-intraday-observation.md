# 精确推荐与盘中 K 线观察

## 推荐目录

`SourceDefinition.upstream_groups` 声明服务上游归属，`recommendation_priority` 可按精确绑定返回非负用途优先级和中文理由。数值越小越优先；没有明确依据时不声明。目录兼容增加可选 `credentialRequired`、`recommendation`，旧消费者升级前应核对严格解析契约。

`readEvidence:true` 只复用与当前适配修订、凭证代次、有效期和已验证读取范围相符的既有准入，不新增实测数据库。已配置凭证、接口权限成功或健康状态不能代替读取证据，也不把已验证标的和窗口扩展为全市场历史质量保证。

当前复用目录已经核验的事件准入快照，不为基础行情额外查询或要求人工准入。没有可比较证据的接口不获得质量加权；当前来源没有声明用途数值优先级时，继续使用同等条件待选择规则。

## 请求保护

AKShare、efinance 的随机间隔、Tushare 本地分钟计数、公共随机等待、台湾机构读取间隔、搜索批次间隔及 ETF 单标报价十分钟频次阻断已退出执行。旧内部方法和构造参数兼容保留，但不等待、不计数、不写频次记录；历史频次表与记录保留，不做结构升级。`fetch_tushare_stock_list.py` 的主动间隔也已移除。

SDK 自带保护、请求超时、失败重试退避、熔断、单标读取、资源并发锁和权限检查冷却继续保留。限频和额度错误不在同一目标上立即重复请求，备用仅沿当前路由选择。上游 HTTP 429、额度耗尽、401 和403分别保留限频、额度、认证及权限分类，不能把付费功能限制统一解释为额度不足。

## 只读采样入口

运行时使用 `ReadOnlyProbeStore`，SQLite 以只读模式打开并启用 `query_only`。下列目录预检不请求上游：

```bash
python -B -m src.services.thesis_ledger_intraday_observation --markets CN HK US --plan
```

实际时间编排由相邻 infra 的 `scripts/intraday-provider-observation.mjs` 负责。每批调用模块一次，第二批起通过 `--previous-stdin` 传入累计回执；最多四批、每来源每市场十二次逻辑查询，共享同一供应商多个服务上游的预算。每周期选择一个已就绪的具体绑定作为代表，不把未采接口认作通过。

采样直接消费来源精确绑定，适配器使用 `cache=False`，绕过应用结果缓存，读取前后核对凭证及本地资格。代表标的为沪深 `600519.SH`、香港 `00700.HK`、美国 `AAPL.US`，按各市场当地日期取1分钟、60分钟和日线。明确限频、额度或权限限制后停止该来源该市场的其余读取。逻辑查询可能包含 SDK 的身份核对或分页请求，十二次不是十二个 HTTP 包。

记录计划时间、每次实际起止时间、延迟、绑定修订及最后三根 K 线的 OHLCV。`adapterComplete` 与绑定暴露的原始 `sourceConfirmation` 分开；未暴露原始标识时明确记空，不能据此推断上游没有标识。同根数值变化、新 K 线出现和未变化分别报告，未变化不能证明来源只返回确认数据。
