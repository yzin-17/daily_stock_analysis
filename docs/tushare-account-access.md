# Tushare 账号等级与本地权限记录

行为与验收由主仓[账号权限规格](../../thesis-ledger/docs/specs/2026-10-09-unified-data-capability-adapter.md#account-access-persistence)和[原实施任务](../../thesis-ledger/docs/tasks/2026-10-09-unified-data-capability-adapter.md)维护。

## 配置与检查范围

账号积分由用户填写，独立权限只勾选已经单独开通的项目。按用户指定的[积分权限表](https://docs.qq.com/sheet/DT0FIYUxYakJ5c1FF?tab=BB08J2)及其逐接口规则，当前接入范围为：`daily` 至少 120 分、`fund_div` 至少 400 分、`fund_daily` 至少 2000 分、`cyq_chips` 至少 5000 分；`hk_daily` 和 `rt_k` 使用独立开通项。接口门槛由来源模块拥有，变更时同步更新等级规则版本。

配置 API 的 `settings.accountLevel` 包含整数 `points` 与 `independentApis`，后者只接受 `hk_daily`、`rt_k`。权限检查请求可带同一 `accountLevel` 作为草稿。低于积分门槛或未勾选的独立接口返回 `state=not_included`、`attempted=false`；不会发送该接口请求。未提供等级的旧调用沿用原检查行为。

保存时先检查范围内的接口，复用同输入的短期草稿结果；配置与权限记录在同一个 SQLite 事务提交。未知结果和未包含项不强制阻止保存，无效凭证被拒绝。普通精确检查也跳过当前等级未包含的项目。

## 保存、恢复与失效

本地 `thesis_ledger_account_access` 表保存权限报告和私有 HMAC 绑定，不保存凭证原文。表仅在保存权限时按需创建，当前配置读取不隐式建表。原有控制库和卷保留，新增表不删除旧记录或改变业务数据。

记录绑定实际账号、认证方式、有效端点、凭证代次、等级和规则版本；重启后可以恢复。单纯启停时复用原检查时间并投影到当前配置代次；凭证、端点或等级改变后原结果不适用于新配置。移除页面凭证同时清除该账号等级，环境凭证需要单独确认等级。草稿有效五分钟；已保存记录持续保留，权限升级后由用户主动更新。

注册表只公开账号等级，不透传其他内部 `settings`。功能说明、路由新选项和检查入口只展示已确认可用的功能；配置页说明未包含的数量。来源启停、已保存路由、准入和旧冻结结果仍按原机制处理。

## 兼容与回退

新增字段和 `not_included` 状态需要与主仓 Schema/API/客户端同时更新；旧严格客户端可能将新报告判为不可用，不能只更新 DSA。回退代码时保留本地 SQLite，新表可被旧代码忽略；不通过删除数据库恢复旧显示缓存。

这份记录仅证明账号接口访问情况；数据覆盖、价格口径、历史事实和业务消费由各自的合同与验收维护。
