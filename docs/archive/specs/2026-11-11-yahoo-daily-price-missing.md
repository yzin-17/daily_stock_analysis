# Yahoo 日线价格缺失排查与修复

本轮已完成并归档，范围与验收见[归档任务](../tasks/2026-11-11-yahoo-daily-price-missing.md)。当前来源合同由 [Yahoo 日线完整窗口](../../design/thesis-ledger-yahoo-daily-window.md)维护。

## 目标与范围

核对 `600519.SH` 前复权、`2026-09-24` 至 `2026-11-10` 完整窗口的 Yahoo 价格缺失，区分上游原始响应、yfinance 解析／复权与本地适配三个阶段。实现证据支持的最小修复；修复后复用生产窗口校验，不补造价格、复权因子、成交量或上市事实，不静默删除不完整行。

## 约束

- 保留原策略、历史回测、凭证、准入及真实主备路由。
- 观察同一次生产读取的转换前后数据，诊断只记录字段缺失统计、公开日期及脱敏代码位置，不输出凭证、Cookie 或供应商异常原文。
- 本轮新增 Yahoo 最多 8 次逻辑诊断读取：前三次分层／原始响应／单日对照，第 4 次目标超时，第 5 次恢复核对确认两日窗口仍缺价，第 6 次单日补取被错误的聚合时限中断，修正后股票与 ETF 各一次；不机械重复确定性失败。一次生产读取至多两个 SDK 调用，每次仍最多 4.5 秒，聚合最多 8 秒且不改变既有 `run_probe` 外层 8 秒截止；不扩大权限，不创建真实回测。
- 原始字段缺失、复权依据缺失和网络／权限失败分别处理。不能以未复权价格冒充前复权，也不能通过关闭校验获得成功。

## 验收标准

- AC-01：同一次读取的阶段统计明确缺失发生位置，并形成可复核、脱敏证据。
- AC-02：如有本地适配缺陷，最小修复拥有正常与拒绝测试；来源身份、窗口、价格口径、错误和缺日边界保持。
- AC-03：适用的定向、合同与仓库门禁通过；经正式最小更新入口同步，目标运行态验证固定完整窗口，明确仍受外部数据限制的项。
- AC-04：实际原因、修复或无法修复的依据、调用预算、控制状态与历史保全形成记录。

状态由[任务](../tasks/2026-11-11-yahoo-daily-price-missing.md)维护。本轮承接[既有来源检查](../../../../thesis-ledger/docs/evidence/2026-11-11-backtest-source-compatibility.md)中的 Yahoo 缺价现象，不将此前观察当作上游原始数据结论。

## 已确认的修复合同

完整窗口及两日窗口的 Yahoo 原始响应均缺少末日收盘，只有该日独立读取完整，因此补取必须是单日请求。两个请求先取 Yahoo 原生 OHLC、Adj Close，不提前复权以免 SDK 把仍完整的原始价格变为空值。仅当唯一末日缺少价格，且该日至少三项原始 OHLC 和成交量已知时触发。

单日返回的全部原始价格、Adj Close 与成交量必须有效；该日所有已有原始价格及成交量须一致，浮点比较仅容纳 `1e-10` 相对或 `1e-12` 绝对计算误差。只填原空字段，不覆盖已有值、不补成交量、不扩展窗口。补齐后复用当前 yfinance 的 `utils.auto_adjust` 完成前复权，不自行计算因子。前复权语义仍为现有的 provider-defined，不认证统一锚点或严格 PIT。

中间／多日缺价、缺少同日价格或成交量对照、无有效返回、价格冲突及超时继续拒绝。来源适配的读取帧保留两次 SDK DataFrame 摘要、补取日期、同日对照字段，明确摘要不是原始 HTTP 字节。生产传输校验核对一或两次读取，在线 qfq 使用新的适配／分页修订；原 Share 参考窗口与历史记录保持。无需通用 `repair=True`，不引入其他价格／分红修复。

首次实现误将旧适配的单次 `yf.download(timeout=4.5)` 参数解释为整个读取的硬截止；旧实现没有该聚合限制，既有诊断使用 `run_probe(timeout_seconds=8)`。实际多次 SDK 调用还包含认证／时区等内部开销，错误的 4.5 秒聚合限制会使补取无法完成。最终每次 SDK 参数仍不超过 4.5，两个调用在最多 8 秒的聚合截止中分配剩余时限，不放宽价格／窗口／一致性校验或外层诊断截止。
