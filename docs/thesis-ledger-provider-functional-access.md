# ThesisLedger 数据源逐功能权限

同一供应商共用一个来源身份、配置入口和启停选择。费用档位不作为新的 `providerId`；是否可用由精确能力、凭证和实际接口结果共同表达。

## 契约与执行边界

- 来源通过 `SourceDefinition.route_requires_credential` 声明精确能力是否需要凭证；没有声明时沿用 manifest 的要求。权限检查、目录就绪状态、日线/分钟修订和基础执行门禁消费同一声明。
- `accountAccessSupported` 表示可逐功能检查；`accountLevelSupported` 仅表示支持账号积分及独立权限的等级契约。Tushare 声明两者，TickFlow 只声明前者。
- `allowed` 必须来自实际请求；缺凭证不尝试对应接口。认证失败、明确缺权限、限流、网络失败、未检查和过期保持独立。单项失败不抹去其他功能已取得的结果。
- 检查固定凭证快照及配置代次。所有支持检查的来源均将当前配置的结果长期保存在既有权限记录表中，超过五分钟、关闭页面或进程重启仍可读取；凭证、端点或账号等级改变时失效，权限变化可手动更新。检查不会自动启用数据源、购买权限或生成业务读取事实。
- 未保存输入的检查结果采用五分钟有界缓存，不发布为当前权限。相同输入在缓存有效期内保存时，原子绑定新配置代次并转为长期记录，无需重复请求上游；普通来源没有匹配检查结果时只保存凭证，不自动检查。Tushare 保留原等级检查契约。
- 旧版仅存在内存中的结果无法在重启后恢复，需要手动重新检查一次。权限记录只保存私有指纹和脱敏结果，无等级来源不写 `accountLevel:null`。
- 首次明确限频后暂停该来源本轮后续请求；相同输入按原限频检查时间冷却至少60秒，期间复用结果且不延长冷却。当前记录跨重启保留冷却，草稿沿用有界缓存；冷却不是自动重试或上游配额恢复承诺。
- 部分检查完成后手动补查只请求待确认项，保留已确认结果及时间，不让重复检查耗尽预算。Tushare 原每轮最多6次、TickFlow 最多14次的预算保持；同一服务进程中同源检查互斥，避免并行重复调用。全部功能已有确定结论时仍支持手动全量更新。
- Tushare 来源声明同一接口的权限分组：股票和ETF分钟的五个周期分别复用 `stk_mins`、`etf_mins` 一次请求的接口权限事实。单接口限频只暂停该组，其他接口可继续；全局HTTP429仍暂停来源。未知窗口的Tushare限频保守冷却一小时，其他来源仍为60秒。只有实际尝试过的限频事实能建立冷却，旧版未请求的暂停项不会阻塞其他接口。

## TickFlow

统一身份及上游目标为 `tickflow/tickflow`，包含3项股票日线、10项股票/ETF分钟及1项股票实时行情。日线沿用已验证的沪深 A 股免凭证接口及原完整窗口限制；免费传输不携带页面或环境 Key。分钟和实时报价使用账号接口，缺 Key 时保留不可用原因。

一次权限检查最多14次接口请求，18秒总预算，每次最多3秒且关闭 SDK 重试。无 Key 仅发起3次日线接口检查。权限成功不代表完整历史、历史身份或可成交行情已通过验证。

旧 `tickflow-free` 不再注册，历史冻结结果保持原值。部署前检查当前 Desired：如仍含旧目标，通过主仓政策 API 新建版本，将其映射为同一能力的 `tickflow/tickflow` 并按原顺序去重；不直接改写历史政策、凭证或启停选择。2026-11-09 的目标政策194没有 TickFlow 目标，因此本次无需政策写入。
