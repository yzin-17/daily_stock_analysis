# 文档目录与生命周期

本仓使用[三仓统一规则](../../thesis-ledger/docs/DOCUMENTATION-GUIDE.md)，文档从 [README](README.md) 进入。

- `design/`：接口架构、Provider 适配和来源语义，见[长期设计](design/README.md)。
- `specs/`：数据服务需求范围与验收合同，见[规格导航](specs/README.md)。
- `guides/`：目录维护、贡献规范、来源归属、许可证、凭据与 NAV 生产操作。
- `evidence/`：验证记录、原始材料和测试固定输入；当前来源验证从[证据导航](evidence/README.md)进入。
- `archive/`：已完成任务与已退役原产品资料；历史正文、原语言和关联素材保持。

当前 Task 状态与跨仓接续见 [README](README.md#当前任务)。只有存在执行义务时才建立 `tasks/`；有独立审查正文时再建立 `reviews/`。`INDEX.md` 只链接文档中心，`CHANGELOG.md` 保留上游工具约定路径。

Task 只在完整范围和最终核对完成后归档；来源权限及主仓产品门禁仍由各自活动 Task 持有。仍有效的合同不因实施完成归档。共享和 CI 证据保持单一正文，已结案且仅属于归档任务的证据可进入 `archive/evidence/`。

归档修复跨仓引用、相对链接、锚点和实际文件消费者。冻结原始材料与摘要保持；中文、英文和繁体历史资料一起移动，保留原语言与适用基线。
