# 精确能力首次使用与验证记录

## 执行与状态

已适配并由当前配置选中的普通查询、行情和报价可直接发起首次请求。能力验证记录缺失表示“未验证，可尝试”；一次完整成功后保存“已验证”。明确撤销、停用、缺凭据、接口权限拒绝和实际请求合同失败分别保留原原因。

`QueryBinding` 的普通请求不再以人工准入记录作为第一次调用的前提；`EventBinding` 仍要求本次数据合同所需的原文、身份及可见性事实。能力验证说明接口曾完整成功，不替代历史完整覆盖、证券身份或其他金融事实。成功观测但历史覆盖未知的事件保持其原合同语义。

## 存储所有权

`src/services/thesis_ledger_capability_verification.py` 拥有 `thesis_ledger_capability_verification`。表在首次成功发布的事务内以增量方式创建，沿用 DSA 本地控制库现有增量存储模式，不修改或重建历史表。

记录按精确能力键和 `providerId/upstreamSource` 归属，私有 HMAC 绑定来源配置版本、凭据版本、环境／页面连接值及适配修订。持久载荷只包含验证状态、首次成功时间、配置版本和请求证据摘要；不保存凭据原文或完整业务响应。配置与适配修订变化后旧记录读为未验证，新的完整成功替换相应记录。适配行为变化时继续按已有规范维护适配修订。

同一上下文只保留首次成功，并发发布幂等。发布时再次比较配置和适配快照，旧版本的迟到成功不能认证当前配置。临时错误与短时健康由原机制维护，不抹去同版本曾成功的事实。

## 成功发布边界

- 完整日线窗口：`api/thesis_ledger_bar_read_v3.py` 在覆盖、分页、来源和响应投影通过后发布；该模块拥有从原聚合 API 提取的完整窗口应用编排。
- 日线／分钟图表：标准图表响应投影通过后发布，不授予回测完整覆盖。
- 普通查询与报价：当前执行面完成本能力合同、政策、目标及凭据复核后发布。
- 事件：原文及身份检查之后建立验证上下文，来源合同与最终协议投影通过后发布；无效原文不能为验证记录触发提前解密或 SDK 访问。
- 精确能力检查：实际读取与配置基线复核成功后保存；fixture 和未保存的草稿凭据不认证当前配置。

`unavailable`、`partial`、未知或失败状态不发布。合法空结果可证明查询能力成功，仍保持原业务空集语义。缓存继续受原来源、配置和请求上下文约束。

## 目录与消费

能力目录通过可选 `verification` 字段提供 `unverified` 或携带证据的 `verified`。验证元数据不改变路由目录的控制修订，避免一次成功使正在执行的冻结请求失效。未知账号访问记录在同能力、同配置真实成功后可投影为可访问；明确失败仍独立表达。

ThesisLedger 的共享 Schema 与 Server 保留该字段；Desktop 在现有能力说明与选源中展示结果，未知检查状态可以新选择。原来源启用与主备选择由用户配置，不由验证机制改写。

产品合同由[主仓规格](../../../thesis-ledger/docs/specs/2026-11-11-capability-first-use-verification.md)维护；实现与验收见[归档任务](../../../thesis-ledger/docs/archive/tasks/2026-11-11-capability-first-use-verification.md)及[验证记录](../../../thesis-ledger/docs/evidence/2026-11-11-capability-first-use-verification.md)。

## 真实验收入口

`scripts/local-runtime/verify-capability-first-use.sh` 只对运行中的本开发 DSA、已启用并选中的精确日线来源发起一次最多 93 天的正式 HTTP 请求。读取后由新存储实例核对记录，并比较来源配置及路由的控制摘要。已验证时直接核对持久结果，不重复访问上游；该命令不改配置、路由或业务历史。
