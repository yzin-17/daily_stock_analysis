# RQData ETF 基金身份与分红币种证据

本页说明 `read_rqdata_mapped_fund_event` 的身份读取合同。主仓 Schemas 原文合同和 Server 在线/离线消费者已完成；DSA 精确事件库存和 HTTP 生产入口已接入此接缝并同步目标。账号保存、库存登记或证据文件存储成功均不授予事件准入；目标正向请求与真实来源审核仍是独立门禁。

## 证据来源与审核

[RQData 基金官方文档](https://www.ricequant.com/doc/rqdata/python/fund-mod)说明基金查询代码不带交易所后缀，`fund.instruments` 还支持历史转型合约。不能仅把 `.SH/.SZ` 去掉后就认定查询身份正确，也不能由 `PublicFund` 或名称推定 ETF。

审核者必须分别核实规范证券与基金查询代码的对应、ETF 资产类型及适用历史日期范围；分红还需核实现金分红币种。当前实现只接受数字部分一致的直接映射，历史转型合约或其他查询别名拒绝，不能以当前合约替代已消失的历史身份。交易币种、基金分类及拆分权限不证明现金分红币种或分红权限。

证据原文保存在既有 `MappingEvidenceStore` 中，最大 1 MiB，以原始字节的 SHA-256 寻址。只有外部审核后当前准入的 `evidenceRef/evidenceSha256` 同时绑定该原文，读取才使用它。文件存储、哈希相等和下面的字段校验只证明绑定及格式，不证明原文引用所声称的外部事实真实；真实核验仍属独立来源门禁。

## 内部文件合同

顶层必须只有 `contractVersion: 1`、`kind: "rqdata-fund-identity"` 和 `mappings`。映射数量为 1–1000，整个集合中每个规范证券只能出现一次，重复 JSON 字段拒绝。

每条映射包含：

| 字段 | 要求 |
| --- | --- |
| `symbol` | 中国交易所规范证券，六位数字加 `.SH` 或 `.SZ` |
| `instrumentType` | 固定 `ETF` |
| `queryFundCode` | 六位无后缀查询代码；当前必须与 `symbol` 的数字部分一致 |
| `scopeDateFrom` / `scopeDateTo` | 经审核的真实、有序日期；必须受当前准入范围覆盖 |
| `observedAt` | 身份证据的实际核验观察时刻，必须带时区，不晚于准入登记、读取时刻和 `dataAsOf` |
| `identityEvidence` | `documentUrl` 为不含账号的 HTTPS 原文引用，`documentSha256` 为原文摘要；两字段必填 |
| `dividendCurrencyEvidence` | 拆分可省略，分红必填；含 `currency`、独立 `documentUrl/documentSha256`，当前支持 `CNY/HKD/USD` |

读取请求的整个窗口必须落在对应映射和当前准入的范围内；规范证券、精确事件能力及 `rqdata × rqdata` 来源必须一致。缺映射、缺币种、损坏证据、撤销、过期、未来记录或观察均拒绝。目录和当前准入只在有效记录已存在后核对账号修订，缺准入不解密 RQData 账号；隔离 SDK 初始化前必须完成身份/币种校验。读取结束重新核对当前准入、证据字节与账号修订，晚到结果不能跨越变更。

## 返回与完整性边界

内部读取结果和公开事件 V3 响应保留标准化事件及原始内容修订，附带 `identityEvidence: { ref, sha256, content }`。Server 在线与离线消费者按原始 UTF-8 字节重验摘要、身份范围和独立币种；生产入口同时复核策略、目录、准入和账号修订。默认 SDK 总期限为 30 秒、本地最多 2000 行，读取只发起一次，不改源或隐式重试；历史覆盖仍不完整。

原始事件内容版本与身份映射证据摘要分别保留，不能把本地身份核验包装成正式上游事件修订。覆盖继续使用原读取器的不完整结论；单基金请求成功、映射审核或全部响应行到达不证明事件全集或历史修订覆盖。

本地测试使用合成准入、原文引用与受控 SDK 响应，验证实际加密 SQLite、原文文件、鉴权 HTTP、真实 spawn 和标准化接线；新增 11 项、相关组合 166 项通过。两个实际生产编排输出通过主仓 Server Schema 与摘要重验。目标六份源码摘要一致、服务 healthy；当前未应用 V3 策略，两种能力的实际 HTTP 请求均拒绝。真实 ETF 映射、币种审核、账号权限、完整历史、目标正向请求和真实冻结验收仍未完成。
