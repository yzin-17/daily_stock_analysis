核对日期：2026-10-19。对应 [D0](../archive/tasks/2026-10-18-data-only-service.md)。本叶只读取源码和构建定义，不导入应用，不运行来源、模型、数据库或 Docker 操作。

## 输入与完整性

[逐路径清单](2026-10-19-data-service-inventory.jsonl) 使用 JSON Lines 保存：1063 条源码/客户端/构建路径、2410 条直接本地导入、177 条 API 路由装饰器声明、552 条 Python 测试关联、43 条表定义、20 个生产来源注册，以及包初始化、条件/函数/类型导入和强连通分量。路径含当前未提交文件；1208 个 Python 文件均可被 AST 解析。Python 源码集合指纹为 `b49145558c19093d7cb44090d24bd32133958ec77a14a997e9c097fa4e72655f`。

清单 allDirectConsumers 另列全部 Python 直接/包初始化引用，包含类型、函数、可选和延迟分支；数据根可达性不是唯一删除依据。索引生成脚本与 JP/KR CSV 已单独列为数据保留，默认配置样例和打包忽略输入纳入矩阵。

这是实施前的静态基线。路由声明不等于运行时 OpenAPI 清单，测试关联不等于执行覆盖率；DG1 必须通过真实模块和独立进程补齐。`state` 中的候选不能直接作为删除指令。非 Python 资产的归属还结合下文的构建载荷及显式文件引用；不能把未进入 Python 导入图当成消费者为零。

导入解析包含每级包初始化，并区分模块/类体、函数、类型条件和延迟属性。`src.services`、`src.agent` 等包的 `__getattr__` 按实际请求成员解析；仅加载包不代表执行其全部延迟分支。源代码动态模块名的六类解析依据位于清单首条元数据：有限注册表、固定调用/元组、产品输出 SDK，以及待退役 CLI 的打包探针。没有把静态可达性当作已经发起外部请求。

## 删除闭包与逐路径回归

完整可能导入图存在八个非平凡强连通分量。排除原生 API/CLI 入口后，Agent、分析、通知/Bot、部分组合风险及决策信号仍形成 50 模块的 C1。D5、D6、D7、D8a、D8b2 涉及 C1 的部分必须共同断开回边并原子验证。外围路径按引用的反向拓扑分闭合子集处理：调用方先退役，类型/延迟引用与包重导出一并处理，随后才移除被调用方；各目录父项分别维护完整出口，不作为组内虚假启动前置。不能先删除 Agent 目录，再期待后续分析/通知叶修复其悬空导入。

D8b 的告警与决策信号、D8c 的选股与回测分别有独立写集，拆为子叶；另补 D8d 处理原生登录/系统配置/用量/旧股票页面胶水及最终无消费者的业务存储代码。上述均属于现有纯数据化范围；不删除业务数据库/文件。原 D9b 需要等待这个源码清理出口。
